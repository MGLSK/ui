Install

Copy starter/ (it carries its own assets/) or copy dist/ into your project, then link two files. Fonts are referenced as ../fonts/… from the stylesheet, so keep css/ and fonts/ as siblings.

A minimal page

Every page uses the same shell: a skip link, an .app wrapper, a .sidenav, a .topbar and one main. Start from the starter or copy any example.

Use one h1, then h2 card titles, and keep the landmarks. The component pages show live markup you can copy for every piece.

How it works

  • CSS-first. Components are classes (.btn, .card, .table…). Most work with no JavaScript.
  • Declarative JS. Behaviour attaches through data- attributes and initialises on load.
  • Icons. <i data-icon="home"></i> becomes an inline SVG; add your own to MGLSK.icons.
  • Dynamic markup. After you inject HTML call MGLSK.init(root) so behaviour attaches to the new nodes.

Theming

Mode and accent are runtime switches, no rebuild. Everything is driven by CSS variables; the accent is stored as an r g b triplet so tints and glows can be derived.

Choices persist in localStorage (mglsk-theme, mglsk-accent). To avoid a flash of the wrong theme, every page carries a small inline script in <head>; copy it from any page here. Brand overrides go after the stylesheet:

TokenUse
--accent-rgb, --accent, --on-accentAccent for the current mode; rgb(var(--accent-rgb) / .2) for tints; readable text on an accent fill.
--bg --surface --surface-2 --border --text --mutedNeutrals.
--success --warning --danger --infoStatus colours, independent of the accent.
--s1…--s6Chart series; --s1 follows the accent.

See the live theming page.

Forms and validation

Wrap a form in data-validate. Controls are checked on submit and on blur; invalid controls get aria-invalid and an error linked by aria-describedby, and the first error takes focus. Always use a real <label>.

Live examples: Field, Select, Date picker, OTP, Settings page.

Dialogs, toasts and menus

Dialogs use the native <dialog>; toasts and confirms are promise-based helpers.

Charts and the network graph

Dependency-free SVG charts that follow the theme, re-render on resize and ship a hidden data table for screen readers.

The network graph draws nodes as isometric cubes on a floor grid, joined by animated data links. Hover or focus a node to light up its neighbours; select with click or Enter.

OptionMeaning
nodes[]{id, label, x, y, z, group, status, size}; status is ok | warn | danger.
links[]{from, to, status}; "down" draws a red dashed link with no traffic.
routing"ortho" (default, along the grid axes) or "straight".
colorsMap a group to a colour slot 1–6; default is order of first appearance.
heightFixed height in px; automatic (max 520) when omitted.

Effects and motion

The dot field, scanlines and grain are decorative. Put data-fx="off" on <html> to disable them (the [data-fx-toggle] button does this and remembers it), or add data-no-field anywhere on a page to keep the scanlines but skip the WebGL field. prefers-reduced-motion stops animation and renders a single static WebGL frame. Without WebGL the dot field is skipped and the particle logo falls back to 2D dots.

Accessibility

Built to WCAG 2.2 AA and re-checked on every test run: axe-core finds 0 violations on every page in both themes, plus a keyboard and behaviour suite (focus management, ARIA state, live regions, 320 px reflow, forced colours). Not yet verified: manual screen-reader testing, Firefox and Safari. The per-component keyboard map and the author checklist are in ACCESSIBILITY.md in the repository.

  • Label every control with a <label> or aria-label; placeholders are not labels.
  • Keep one h1, then h2; keep the skip link and landmarks.
  • Give icon-only buttons an aria-label; give dialogs a heading.
  • Never remove focus outlines; do not hide information in tooltips.

Browser support

Uses <dialog>, :has(), color-mix(), CSS mask, scroll-snap and WebGL 1: roughly Chrome/Edge 111+, Safari 16.4+ and Firefox 121+. Only Chromium has been tested so far.
